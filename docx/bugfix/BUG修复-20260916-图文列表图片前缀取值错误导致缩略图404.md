# BUG 修复 · 20260916 · 图文列表图片前缀取值错误导致缩略图 404

- 影响功能：feat-007（首页轮播图 / AI 智能推送 / 最新内容）、feat-008 前的专题列表页
- 严重级别：中（不减功能，但接口图全部不显示，退化为静态兜底图 —— 违反不变式 9）
- 状态：已修复并验证

## 1. 现象

首页轮播图与各列表缩略图**从不显示接口返回的图片**，一律呈现 `static/images/cover-greatwall.png` 等本地兜底图或空白底；网络面板中图片请求返回 **404**。

## 2. 复现步骤

1. 登录后进入首页（或专题列表页）；
2. 观察轮播图与列表缩略图 → 全部为静态兜底图；
3. 直接请求接口返回的图片地址：
   - `https://szdj.cdszxjc.com/tuwen/732d6ffa6897c5bbe164b84c19129aa6.png` → **404**
   - `https://szdj.cdszxjc.com/ossdir/tuwen/732d6ffa6897c5bbe164b84c19129aa6.png` → **200 image/png**

## 3. 根因

`apituwen/tuwenliebiao`、`tuwenfuliebiao`、`tuwencaozuoliebiao` 的响应结构为：

```json
{
  "obj": { "ossdir": "ossdir" },      // ← 文件前缀只在这里
  "list": [
    { "settuwenid": 16, "wenjianurl": "/tuwen/1edc….jpg" }   // ← list 项没有 ossdir 字段
  ]
}
```

原实现写成 `resolveFileUrl(item.ossdir, item.wenjianurl)`，而 `item.ossdir` 恒为 `undefined`，于是拼出**缺少前缀**的 `/tuwen/xxx.png` → 404 → `<image>` 触发 `@error` → 落兜底静态图。因为兜底图"看起来正常"，缺陷在 feat-007 验收时被掩盖。

## 4. 修复方案

1. `src/api/modules/tuwen.ts` 新增 `envelopeOssdir(res)`，从响应 **`obj.ossdir`** 取前缀，并在类型注释中写明"list 项不含该字段"这一实测事实；
2. 调用处改为 `resolveFileUrl(ossdir.value, item.wenjianurl)`：
   - `src/pages/index/index.vue`：新增 `ossdir` 状态，在 `loadData()` 中由 `bannerRes/aiRes/latestRes` 提取；
   - `src/pages/topic/index.vue`：新增 `ossdir` 状态，在分页加载时提取（`envelopeOssdir(res) || ossdir.value`，兼容首屏失败后续页成功）；
3. 详情页（feat-008）直接使用 `tuwenxiangqing` 的 `obj.ossdir`，并支持列表页传入 `ossdir` 作首屏占位；
4. 同步更新 `AGENTS.md` 不变式 4（写明前缀位于 `obj`、list 项无此字段、正反例 URL 与状态码）。

## 5. 改动文件

- `src/api/modules/tuwen.ts`（新增 `envelopeOssdir`）
- `src/pages/index/index.vue`（ossdir 提取 + 缩略图/轮播拼接）
- `src/pages/topic/index.vue`（ossdir 提取 + 缩略图拼接）
- `src/pages/detail/index.vue`（详情头图 ossdir 来源）
- `AGENTS.md`（不变式 4 / 不变式 9 字段清单）
