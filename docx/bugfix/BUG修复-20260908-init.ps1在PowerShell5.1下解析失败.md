# BUG 修复：`init.ps1` 在 Windows PowerShell 5.1 下解析失败（基线假绿）

日期：2026-09-08

## 现象

在仓库根运行 `./init.ps1` 时，脚本未执行任何检查即抛出解析错误：

```
标记“||”不是此版本中的有效语句分隔符。
字符串缺少终止符: "。
语句块或类型定义中缺少右“}”。
```

同时脚本内的中文提示在控制台显示为乱码（如 `澹扮О瀹屾垚鍓嶉噸鏂拌繍琛?./init.ps1`）。
运行结束后 `$LASTEXITCODE` 仍为 `0` —— 表面"通过"，实际基线检查一条都没跑。

## 复现步骤

1. 打开 Windows PowerShell（5.1）
2. `cd` 到 `cdp-party-building-uniapp/` 之外的任意目录（或仓库根）
3. 执行 `./init.ps1`
4. 观察到上述解析错误，且不产出任何 `npm run` 结果

## 根因

1. **PowerShell 版本差异**：脚本中用 `node -e "…scripts||{}…"` 探测 package.json scripts，字符串内的 `||` 被 Windows PowerShell 5.1 当作管道链运算符解析（`||` 是 PowerShell 7 才引入的运算符）→ 整段脚本语法解析失败。
2. **文件编码**：`init.ps1` 以 UTF-8 无 BOM 保存，Windows PowerShell 5.1 按 ANSI 读取，中文字符串被解析成乱码，进一步破坏字符串闭合。
3. **掩盖问题**：脚本"未找到 package.json"的分支是 `exit 0`，即使工程目录漂移（如重命名为 `cdp-party-building-uniapp/`）也会报"非失败"，制造假绿基线。

## 修复方案

重写 `init.ps1`：

- 探测表达式去掉 `||`，改用三元运算符：`const s=(typeof p.scripts==='undefined')?{}:p.scripts`
- 文件以 **UTF-8 with BOM** 重新保存，保证 5.1 正确显示中文
- 「仓库根与子工程目录均无 package.json」分支由 `exit 0` 改为 `exit 1`，并打印真实期望目录与需同步的文件
- 子工程目录修正为 `cdp-party-building-uniapp`
- 新增 `theme:check` 门禁（置于 `build:mp-weixin` 之后，复用 prebuild 已执行的 `theme:sync`）

## 改动文件

- `init.ps1`（重写，UTF-8 with BOM）
- `AGENTS.md`（新增"改动 init.ps1 的硬约束"：禁 `||`/`&&`、必须 BOM、缺失工程须 exit 1）
- `docx/bugfix/BUG修复-20260908-init.ps1在PowerShell5.1下解析失败.md`（本文件）
