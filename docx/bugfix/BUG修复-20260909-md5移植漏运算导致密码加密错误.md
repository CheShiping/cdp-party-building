# BUG 修复：md5.ts 移植漏一轮运算导致密码加密结果错误

| 项目 | 内容 |
|---|---|
| 发现日期 | 2026-09-09 |
| 发现方式 | 用户在微信开发者工具控制台观察到加密值与预期不符 |
| 严重程度 | **阻断**（登录功能完全不可用） |
| 影响范围 | `src/utils/md5.ts`（`encryptPassword` / `hexHmacMd5`）→ 登录、改密、静默续期 |

## 1. 现象

登录时控制台输出：

```
auth.service.ts:59 原始明文密码： 123456
auth.service.ts:60 加密之后的密码： 6548bb6634539f06c40e927ea72d8e37
```

但 `123456` 的正确加密结果应为 `64d53bde5d769763153159245c619185`（该值已实测可使 `apiuser/login` 返回 `success:true`）。用 `6548bb…` 请求后端返回 `{"success":false,"msg":"用户密码不正确"}` → 登录必然失败。

## 2. 复现步骤

1. 在登录页输入 `admin` / `123456`
2. 观察请求参数 `password` 或控制台日志
3. 实际：`6548bb6634539f06c40e927ea72d8e37`；期望：`64d53bde5d769763153159245c619185`

## 3. 根因

`src/utils/md5.ts` 是仓库根 `md5.js` 的人工 TS 移植，`coreMd5()` 的**第二轮（II）第 62 步之后漏写一行、并把 `c` 的赋值错写成 `d`**：

```ts
// 错误（漏了 x[i+11] 这一步，且 x[i+2] 的结果错赋给 d）
a = md5Ii(a, b, c, d, x[i + 4]!, 6, -145523070);
d = md5Ii(d, a, b, c, x[i + 2]!, 15, 718787259);
b = md5Ii(b, c, d, a, x[i + 9]!, 21, -343485551);

// 正确（与 md5.js 106-121 行一致）
a = md5Ii(a, b, c, d, x[i + 4]!, 6, -145523070);
d = md5Ii(d, a, b, c, x[i + 11]!, 10, -1120210379);
c = md5Ii(c, d, a, b, x[i + 2]!, 15, 718787259);
b = md5Ii(b, c, d, a, x[i + 9]!, 21, -343485551);
```

MD5 每一轮 16 步、每步都参与链式变量更新，漏一步即整个摘要错误。之所以未被发现：原实现**语法合法、类型检查与 lint 均不报错**，且此前只用 Node `crypto` 验证过**参考实现**（`md5.js`），未验证移植后的 `md5.ts` 本身。

## 4. 修复方案

1. 修正 `src/utils/md5.ts` 的 II 轮运算（补回 `x[i+11]` 步骤、修正赋值目标）
2. 删除 `src/services/auth.service.ts` 中打印明文密码与密文的调试日志（违反 uniapp-components-skill A06：日志禁止输出密码）
3. 新增回归防护 `scripts/check-md5.js`：用 Node 内置 `crypto` 的 HMAC-MD5 作基准，对 10 个 ASCII 向量 + 关键密码向量（`encryptPassword('123456') === 64d53bde…`）比对，不一致 exit 1
4. 接入 `npm run check:md5` 与 `npm run verify`（在 theme:check 之后、lint 之前执行）

## 7. 遗留问题

- **非 ASCII 密码**：`md5.js` 为 `chrsz=8`（ASCII）实现，非 ASCII 字符高位被丢弃，与标准 UTF-8 HMAC-MD5 不一致（如 `hexHmacMd5('cds','zh中文')` 与 Node crypto 结果不同）。后端为同款遗留实现，ASCII 密码（数字/字母/常见符号）正常；若需支持中文密码，须先用标准实现与后端对拍确认（建议密码规则限定 ASCII）。
- **移植类代码必须有已知答案校验**：本次教训——人工移植算法不能只靠类型检查，须与权威实现逐向量对拍（已由 `check:md5` 固化）。
